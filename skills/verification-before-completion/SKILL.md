# verification-before-completion

**핵심 원칙**: 주장보다 증거가 먼저다.
항상.

**이 규칙을 글자 그대로 지키지 않는 것은 규칙의 취지를 저버리는 것이다.**

## 입력·주체

**입력**은 지금 하려는 주장과 그 주장을 증명할 검증 커맨드다.
커맨드를 호출자가 지정했으면 그것을 쓰고 아니면 대상 프로젝트의 설정(빌드 스크립트·테스트 러너 설정·CI 정의)이나 실행 중인 플랜의 검증 항목에서 찾는다.
그래도 찾지 못하면 사용자에게 무엇으로 검증할지 묻는다.
검증할 수단이 없으면 검증 불가를 밝히고 통과를 주장하지 않는다.

**주체**는 완료를 주장하려는 당사자다.
아래에서 "에이전트"는 그 당사자가 작업을 위임한 서브에이전트를 가리키고 자기 자신을 가리키지 않는다.

## 철칙

```
새로 돌린 검증 증거 없이 완료를 주장하지 않는다
```

지금 작성 중인 응답에서 검증 커맨드를 직접 돌리지 않았다면 통과한다고 주장할 수 없다.

## 게이트 함수

```
어떤 상태를 주장하거나 만족을 표현하기 전에:

1. 식별: 이 주장을 증명하는 커맨드가 무엇인가
2. 실행: 그 커맨드를 지금 새로, 부분이 아니라 전체를 돌린다
3. 판독: 전체 출력을 읽고 종료 코드를 확인하고 실패 수를 센다
4. 검증: 출력이 주장을 뒷받침하는가
   - 아니면: 증거와 함께 실제 상태를 말한다
   - 맞으면: 증거와 함께 주장한다
5. 그제서야: 주장한다

한 단계라도 건너뛰면 검증이 아니라 거짓말이다
```

## 흔한 실패

| 주장 | 필요한 증거 | 불충분한 것 |
|---|---|---|
| 테스트가 통과한다 | 테스트 커맨드 출력에 실패 0 | 이전 실행, "통과할 것이다" |
| 린터가 깨끗하다 | 린터 출력에 에러 0 | 부분 검사, 일부 결과로 전체를 단정 |
| 빌드가 된다 | 빌드 커맨드 종료 코드 0 | 린터 통과, 로그가 괜찮아 보임 |
| 버그를 고쳤다 | 원래 증상 테스트가 통과 | 코드를 바꿨으니 고쳐졌으리라는 추정 |
| 회귀 테스트가 작동한다 | 수정 되돌림 검증(아래 「핵심 패턴」) | 테스트가 한 번 통과함 |
| 에이전트가 완료했다 | 버전 관리 시스템(VCS) diff에 변경이 보임 | 에이전트가 "성공"이라 보고함 |
| 요구를 충족했다 | 한 줄씩 대조한 체크리스트 | 테스트가 통과함 |

요구를 대조할 원본은 이 작업을 지시한 플랜 문서이고 플랜이 없으면 사용자가 준 요구 목록이다.

## Red Flags. 멈춘다

- "아마", "될 것", "것 같다"를 쓰고 있다
- 검증 전에 만족을 표현한다("좋다", "완벽하다", "됐다")
- 검증 없이 커밋·푸시·PR로 가려 한다
- 위임한 에이전트의 성공 보고를 그대로 믿는다
- 부분 검증에 기댄다
- "이번만"이라고 생각한다
- 지쳐서 일을 끝내고 싶다
- **검증을 돌리지 않은 채 성공을 함의하는 모든 표현**

## 합리화 차단

| 변명 | 실제 |
|---|---|
| "이제 될 것이다" | 검증을 돌린다 |
| "확신한다" | 확신은 증거가 아니다 |
| "이번 한 번만" | 예외 없음 |
| "린터가 통과했다" | 린터는 컴파일러가 아니다 |
| "에이전트가 성공이라 했다" | 독립으로 확인한다 |
| "지쳤다" | 피로는 면제 사유가 아니다 |
| "부분 검사로 충분하다" | 부분은 아무것도 증명하지 않는다 |
| "표현이 다르니 규칙이 적용 안 된다" | 문면이 아니라 취지로 판정한다 |

## 핵심 패턴

**테스트**
```
맞음: [테스트 커맨드 실행] [34/34 통과 확인] "전 테스트 통과"
틀림: "이제 통과할 것이다" / "맞아 보인다"
```

**회귀 테스트(수정 되돌림 검증)**
```
맞음: 작성 → 실행(통과) → 수정을 되돌림 → 실행(반드시 실패) → 복원 → 실행(통과)
틀림: "회귀 테스트를 작성했다"(되돌려 실패를 확인하지 않고)
```
이 절차는 테스트 주도 개발(TDD)의 RED-GREEN과 순서가 반대다.
이미 통과하는 테스트에서 출발해 수정을 되돌려 실패를 만든다.

**빌드**
```
맞음: [빌드 실행] [종료 코드 0 확인] "빌드 통과"
틀림: "린터가 통과했다"(린터는 컴파일을 검사하지 않는다)
```

**요구 충족**
```
맞음: 플랜 재독 → 체크리스트 작성 → 항목별 확인 → 공백 또는 완료 보고
틀림: "테스트 통과, 단계 완료"
```

**에이전트 위임**
```
맞음: 위임한 에이전트가 성공 보고 → VCS diff 확인 → 변경 검증 → 실제 상태 보고
틀림: 에이전트 보고를 그대로 믿는다
```

## 적용 시점

**항상 다음 앞에서**:
- 성공·완료 주장의 모든 변형
- 만족 표현의 모든 형태
- 작업 상태에 대한 모든 긍정 진술
- 커밋, PR 생성, 태스크 완료
- 다음 태스크로 이동
- 에이전트에 위임

**규칙이 적용되는 범위**: 정확한 문구, 바꿔 말한 표현과 동의어, 성공의 함의, 완료·정확성을 시사하는 모든 소통.
