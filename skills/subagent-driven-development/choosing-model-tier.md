# 모델 티어 선택

서브에이전트를 디스패치할 때 어느 모델로 띄울지 정하는 규율이다. groundwork에서 서브에이전트를 띄우는 스킬이 모두 이 문서를 기준으로 쓴다.

**주체**는 서브에이전트를 띄우는 에이전트다. 디스패치되는 서브에이전트는 이 문서를 읽지 않는다.

**경로 기준**은 플러그인 루트다. 다른 문서가 이 파일을 가리킬 때 쓰는 경로는 `${CLAUDE_PLUGIN_ROOT}/skills/subagent-driven-development/choosing-model-tier.md`이고 `${CLAUDE_PLUGIN_ROOT}`는 groundwork 플러그인이 설치된 디렉터리이지 실행 시점 작업 디렉터리가 아니다.

## 티어

티어는 실행 환경이 제공하는 모델을 능력 순으로 늘어놓은 층이다. 이 문서는 그것을 3개 층으로 나눠 쓰고 각 층에 어느 모델이 드는지는 실행 환경마다 다르다.

- **싼 모델**: 가장 빠르고 싼 층
- **표준 모델**: 중간 층
- **가장 유능한 모델**: 최상위 층

## 명시 강제

**서브에이전트를 디스패치할 때 모델을 항상 명시한다.** 모델을 빠뜨리면 세션 모델을 상속하고 그것은 대개 가장 유능하고 가장 비싼 모델이라 이 문서가 무력해진다. 실행 환경의 디스패치 도구가 제공하는 모델 파라미터를 쓴다.

reasoning effort는 이 규율에 넣지 않는다. 실행 환경에 따라 디스패치 시점에 지정하는 수단이 없고 세션 값을 상속한다.

## 구현·설계 태스크

**기계적 구현**(고립된 함수, 명확한 스펙, 파일 한둘): 싼 모델. 플랜이 잘 명세돼 있으면 구현 태스크 대부분이 기계적이다.

**통합·판단 태스크**(다중 파일 조율, 패턴 매칭, 디버깅): 표준 모델.

**아키텍처·설계 태스크**: 가장 유능한 모델. 브랜치 전체를 보는 최종 리뷰가 여기 속한다.

**fix 루프 상승**: 막힌 구현자보다 한 단계 유능한 모델로 올린다.

## 코드 리뷰 태스크

diff의 크기·복잡도·위험에 맞춘다. 작고 기계적인 diff에 최상위 모델이 필요하지 않고 미묘한 동시성 변경에는 필요하다. 작은 수정 diff의 범위 한정 재리뷰는 싼 모델이나 표준 모델이면 된다.

## 조사 태스크

`groundwork:finding-unknowns`의 블라인드 스팟·레퍼런스·스파이크와 `groundwork:dispatching-parallel-agents`의 영역별 조사는 표준 모델. 코드베이스를 훑고 산문으로 보고하는 일이라 싼 모델은 턴을 더 쓴다. 조사 대상이 아키텍처 판단으로 넘어가면 가장 유능한 모델로 올린다.

## 문서 리뷰 렌즈

`groundwork:spec-review`와 `groundwork:plan-review`가 띄우는 리뷰어의 티어다. 판정 기준은 렌즈가 하는 일의 성격이다.

- 문서에 적힌 것을 기준과 대조해 결손을 찾는 렌즈는 **표준 모델**.
- 문서에 적히지 않은 것을 추론해야 판정되는 렌즈는 **가장 유능한 모델**.

| 렌즈 | 티어 | 판정 성격 |
|---|---|---|
| `junior-read` | 표준 | 규범 축과 본문을 대조한다 |
| `completeness` | 표준 | 필수 항목의 결손을 찾는다 |
| `consistency` | 표준 | 절 사이 모순을 찾는다 |
| `clarity` | 표준 | 모호어와 이중 해석을 찾는다 |
| `crossref` | 표준 | 연관 산출물과 대조한다 |
| `facts` | 표준 | 주장과 근거를 대조한다 |
| `spec-alignment` | 표준 | 대응 스펙과 값을 대조한다 |
| `scope` | 최상위 | 이 문서가 담을 범위의 경계를 추론한다 |
| `yagni` | 최상위 | 요구되지 않은 것을 판별한다 |
| `decomposition` | 최상위 | 구현자가 이 태스크에 착수할 수 있는지 판단한다 |
| `intent` | 최상위 | 대화 맥락과 문서의 어긋남을 읽는다 |
| `experience` | 최상위 | 사용자가 겪을 것을 상상해 판정한다 |

리뷰어에 싼 모델을 쓰지 않는다. 아래 「턴 수가 토큰 단가를 이긴다」가 이유다.

## 턴 수가 토큰 단가를 이긴다

실시간과 컨텍스트 비용은 서브에이전트가 몇 턴을 쓰느냐로 늘어난다. 싼 모델은 여러 단계 작업에서 턴을 두세 배 쓰는 일이 잦아 총비용이 더 든다.

- 리뷰어와 산문 서술로 일하는 구현자는 표준 모델을 바닥으로 잡는다.
- 태스크의 플랜 텍스트에 쓸 코드가 그대로 들어 있으면 구현은 옮겨 적기와 테스트라 싼 모델을 쓴다.
- 단일 파일 기계적 수정도 싼 모델을 쓴다.
