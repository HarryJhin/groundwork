# test-driven-development

## Apply test-first implementation

구현자가 대상 변경과 기존 테스트 환경을 확인한다. 테스트 가능한 동작은 실패 테스트를 실행해 예상한 이유로 실패하는 것을 확인한 뒤 최소 구현·통과 확인·리팩터링 순서로 처리한다. 커맨드는 대상 리포 루트에서 실행한다.
테스트 전에 쓴 프로덕션 코드는 지우고 실패 테스트부터 다시 시작한다. 버리는 프로토타입·생성 코드·설정 파일은 변경에 맞는 실행·생성 재현·설정 검증으로 확인할 수 있다.

테스트는 잡아야 할 파손과 관찰 가능한 동작을 검사한다. 기대값은 검사 대상 코드와 독립적으로 유도한다. 소스 문구·상수·비공개 구조가 바뀌었다는 사실만 검사하지 않는다.
목은 느리거나 외부인 경계에 두고, 검증 대상 동작과 필요한 부작용은 실제로 실행한다. 인자·호출 횟수·순서가 계약이면 단언할 수 있다. 단순 전달이나 사람이 읽는 산문에는 절차를 채우기 위한 테스트를 만들지 않는다.

출력은 테스트와 구현, 실행한 검증 결과다. 완료 증거 확인은 `groundwork:verification-before-completion`을 따른다.
