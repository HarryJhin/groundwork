# Scoped re-review prompt template

fix 라운드 뒤 재리뷰를 디스패치할 때 이 본문을 `general-purpose` 프롬프트로 주입한다.  
재리뷰어는 발견이 해소됐는지 검증하고 수정 diff에 새 파손이 있는지 본다.  
새 리뷰가 아니다.  
전체 리뷰는 이미 끝났다.

**목적**: 직전 리뷰의 발견마다 해소 여부를 판정하고 수정 자체가 아무것도 깨뜨리지 않았는지 확인한다.

```text
서브에이전트 (general-purpose):
  description: "태스크 T[N] fix 라운드 [R] 재리뷰"
  model: [MODEL — 필수. SKILL.md 모델 선택 절에 따라 고른다. 작은 수정 diff의
         범위 한정 재리뷰는 싸거나 중간 티어면 된다]
  prompt: |
    너는 태스크 하나의 fix 라운드를 재리뷰한다. 앞선 리뷰가 발견을 냈고 구현자가 그것을 고치려 시도했다. 네 일은 발견마다 판정하고 수정 diff를 살피는 것이다. 그 외에는 하지 않는다.

    ## 태스크

    태스크 브리프를 읽는다: [BRIEF_FILE]

    ## 검증 대상 발견

    [FINDINGS]

    ## 수정

    구현자 리포트를 읽는다(수정 리포트가 끝에 덧붙어 있다): [REPORT_FILE]

    **Fix base:** [FIX_BASE_SHA] (직전 리뷰가 본 head)
    **Head:** [HEAD_SHA]
    **diff 파일:** [DIFF_FILE]

    diff 파일을 한 번 읽는다. 수정 커밋·stat 요약·문맥 포함 수정 diff가 들어 있다. git 커맨드를 다시 돌리지 않는다. diff 파일이 없으면 직접 가져온다: `git diff --stat [FIX_BASE_SHA]..[HEAD_SHA]`와 `git diff [FIX_BASE_SHA]..[HEAD_SHA]`.

    이 체크아웃에서 너의 리뷰는 read-only다. 워킹 트리·인덱스·HEAD·브랜치 상태를 어떤 식으로도 변경하지 않는다.

    ## 범위

    네 범위는 발견 목록과 수정 diff다. 모든 발견을 판정한다. 수정이 스스로 들여온 새 문제를 찾아 수정 diff를 살핀다. 수정이 건드리지 않은 코드는 **재리뷰하지 않는다**. 수정 diff 완전히 바깥의 이슈를 발견하면 「범위 밖 관찰」에 보고한다. 그것은 이 태스크를 막지 않고 루프를 연장하지 않는다. 브랜치 전체 광역 리뷰는 전 태스크가 끝난 뒤에 있다.

    ## 테스트

    구현자가 수정한 코드를 덮는 테스트를 다시 돌리고 결과를 리포트 파일에 덧붙였다. 리포트를 검증되지 않은 주장으로 취급한다. 수정 리포트가 덮는 테스트를 지명하고 그 출력을 보이는지 확인하고 주장을 diff와 대조한다. 그 리포트를 확인하려고 스위트를 다시 돌리지 않는다. 코드를 읽다가 기존 실행이 답하지 못하는 구체적 의심이 생길 때만 테스트를 돌리고 그때도 집중 테스트이지 패키지 전체 스위트가 아니다.

    ## 출력 형식

    네 최종 메시지가 곧 리포트다. 첫 발견의 판정으로 바로 시작한다. 모든 줄이 판정이거나 file:line이 붙은 발견이거나 네가 돌린 확인이다. 서두도 절차 서술도 없다.

    ### 발견별 판정

    「검증 대상 발견」의 각 발견을 순서대로:
    - **[발견 한 줄]** — ADDRESSED | NOT ADDRESSED, file:line 증거와 함께. "시도했음"은 해소가 아니다. 그 구체적 결함이 더는 존재하지 않아야 한다.

    ### 수정 diff의 새 파손

    수정 자체가 깨뜨리거나 들여온 것을 심각도(Critical·Important·Minor)와 file:line과 함께. 깨끗하면 "없음".

    ### 범위 밖 관찰

    수정 diff 완전히 바깥에서 발견한 이슈. 차단하지 않는다. 컨트롤러가 최종 리뷰를 위해 진행 기록에 기록한다. 없으면 "없음".

    ### 판정

    **fix 라운드:** [전 발견 해소, 새 Critical·Important 파손 없음 | 발견이 열려 있음] — 열린 것을 나열한다.
```

**자리표시자**
- `[MODEL]`: 필수. SKILL.md 모델 선택 절에 따른 리뷰어 모델. 작은 수정 diff는 싸거나 중간 티어
- `[BRIEF_FILE]`: 태스크 브리프 파일(구현자가 작업한 것과 같은 파일)
- `[FINDINGS]`: 직전 리뷰의 Critical·Important 발견과 설계 문서의 공백을 그대로 복사해 불릿 하나에 하나씩
- `[REPORT_FILE]`: 구현자 리포트 파일(수정 리포트가 덧붙어 있다)
- `[FIX_BASE_SHA]`: 직전 리뷰가 본 head
- `[HEAD_SHA]`: 현재 커밋
- `[DIFF_FILE]`: `scripts/review-package DESIGN_FILE FIX_BASE HEAD`가 출력한 경로

**재리뷰어가 반환하는 것**: 발견별 판정(ADDRESSED·NOT ADDRESSED), 수정 diff의 새 파손, 범위 밖 관찰, 라운드 판정
