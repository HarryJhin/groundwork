# Design document example

아래는 가상의 공유 할일 앱에서 사용자가 「삭제는 본인 목록에서만 숨기고 취소하면 복구한다」고 확정한 뒤 남기는 설계 예시다. 작은 변경은 같은 내용을 대화로 제시해도 된다.
설계 문서의 경로는 작업 리포 루트 기준이다. 실제 문서에서는 날짜 프론트매터를 파일 첫머리에 펜스 없이 둔다.

```yaml
---
created: 2026-09-16
updated: 2026-09-16
---
```

# Design: hide a shared task for one participant

현재 앱에서 공유 목록의 참여자는 같은 할일을 본다. 개인 할일의 완전 삭제를 그대로 적용하면 다른 참여자의 목록도 바뀐다.
사용자는 공유 할일의 삭제가 본인 목록에만 적용되고 취소할 수 있어야 한다고 정했다. 이 정책을 기존 조회·숨김·복구 기능에 연결한다.

## Scope

공유 할일을 삭제한 참여자의 목록에서만 숨기고, 취소하면 그 참여자의 목록에 다시 나타나게 한다.

## User flows and scenarios

- A가 공유 할일을 삭제하면 A의 목록에서 사라진다. B의 목록에는 그대로 남고 B는 계속 작업할 수 있다.
- A가 삭제를 취소하면 A의 목록에 다시 나타난다. B의 목록과 숨김 상태는 바뀌지 않는다.
- 숨김과 복구 요청이 실패하면 기존 요청 실패 안내를 유지한다. 성공하지 않은 동작을 완료했다고 표시하지 않는다.

마지막 실패 동작은 이 예시에서 사용자가 기존 요청 실패 동작을 유지하라고 명시했다는 전제다. 실제 작업에서 미정이면 경위와 결과를 설명해 확인한다.

## Non-goals

모든 참여자에게 적용하는 공동 삭제 기능은 이번 요청에 포함하지 않는다.

## Design

원본 할일을 남기고 사용자별 숨김 상태로 본인 목록을 필터링한다. 원본을 삭제하면 다른 참여자의 작업 유지라는 정책을 만족할 수 없다.
저장 형태·파일 구조·복구 함수 연결은 실행 시점에 기존 구현을 확인해 정한다.

## Acceptance criteria

- A의 삭제 뒤 A에게는 보이지 않고 B에게는 보인다. 확인: 두 참여자의 목록 조회 결과를 비교하는 테스트.
- A의 취소 뒤 A에게 다시 보이며 B의 상태는 그대로다. 확인: 숨김·복구 전후 두 참여자의 조회 결과를 비교하는 테스트.
- 실패한 요청을 성공으로 표시하지 않는다. 확인: 기존 요청 실패 테스트와 해당 화면의 실패 안내.

검증 커맨드는 프로젝트의 테스트 러너에 맞춰 실행 시점에 정한다. 이 예시는 실제 구현이나 테스트 결과를 주장하지 않는다.
