# using-groundwork

메인 에이전트의 개발 판단 기준이다. 사용자 지시가 우선하며, 특정 태스크를 맡은 서브에이전트에는 적용하지 않는다.

## Decision authority

리포는 현재 동작의 증거다. 새 기능의 목표 정책까지 정해주지 않는다.
서비스 기능·업무 규칙·권한·실패와 재시도 결과의 미정 사항이나 기존 정책을 재검토할 새 맥락은 `groundwork:finding-unknowns`로 다룬다.
질문에는 발견 경위, 선택별 실제 동작과 영향을 설명한다.
파일 구조·모듈·인프라 등 기술 선택은 조사해 자율적으로 정한다. 기술 선택이 서비스 결과도 바꾸면 그 결과를 묻는다.

## Scope and execution

요청이 명확하면 바로 처리한다. 변경 규모나 구현 방법이 여럿이라는 이유로 설계·질문·스킬 로드를 강제하지 않는다.
되돌리기 비싼 기술 변경은 필요한 설계와 근거를 남기되 기술 선택의 승인을 따로 요구하지 않는다.
합의한 설계 문서를 실행할 때는 `groundwork:executing-design`을 쓴다.
완료 전 변경에 맞는 검증을 실행하고 결과와 잔여 문제를 보고한다.
긴 작업은 재개에 필요한 결정·진행·검증·잔여 문제만 파일에 남긴다.

## Code comments

코드를 고칠 때 사용자·리포의 주석 정책을 적용하고, 완료 전 diff의 새 주석·수정한 주석과 변경된 코드에 남은 기존 주석을 대조한다. 함수 추출·이동 뒤 설명이 다른 코드에 붙거나 틀린 설명이 남으면 이번 변경에서 바로 정리한다.
코드·타입·이름·명백한 흐름·일반 API 지식을 풀어 쓴 설명과 작업 이력은 쓰지 않는다. 이유를 붙여도 코드로 얻을 수 없는 프로젝트 제약이 추가되지 않으면 제거한다.
필요한 주석은 실제 식별자·이벤트·상태·조건을 지칭한다. 기술 용어를 모호한 일상어로 바꾸거나 주체와 대상을 지운 서술은 남기지 않는다. 불필요한 주석을 표현만 고쳐 유지하지 않는다.
남은 구현 작업은 `TODO`, 현재 확인된 결함은 `FIXME`로 대상과 필요한 작업을 적는다. 리포의 표기 규약을 따르고 일반 설명으로 미해결 사항을 대신하지 않는다.
구현을 위임할 때 사용자·리포의 주석 정책과 이 절의 기준을 태스크 브리프에 포함한다.

## Context budget

스킬은 현재 작업에 필요한 것만 읽는다. 일반 개발 지식과 이미 읽은 규칙을 반복 로드하지 않는다.
