# docs

이 디렉터리는 **완료된 작업의 기록**이다.
groundwork의 현재 상태를 서술하지 않는다.

현재 상태를 알려면 루트 [README.md](../README.md)와 `skills/`를 본다.
그쪽이 정본이다.

## 낡은 내용을 그대로 두는 이유

groundwork는 자기 방법론을 자기 개발에 적용한다.
그 방법론이 산출물의 수명을 이렇게 정한다.

- **ADR은 수락 후 불변이다.**
  결정을 번복할 때 원 ADR을 고치지 않고 새 ADR을 만들어 원 ADR을 `Superseded`로 돌린다.
  그래서 ADR-0001은 폐기된 결정을 담은 채 남아 있고 `Superseded by: ADR-0004`가 그 사실을 가리킨다.
  규범은 `skills/writing-adr/SKILL.md`에 있다.
- **설계 문서는 `status: closed`로 닫힌다.**
  실행이 끝난 시점의 계획을 그대로 보존한다.
  사후에 현재 구성에 맞춰 고치면 무엇을 계획했고 무엇이 바뀌었는지가 사라진다.

그래서 SPEC-0001은 스킬이 다섯이고 `agents/critic-*.md`가 있던 시절을 서술한다.
지금은 스킬이 열여덟이고 `agents/` 디렉터리가 없다.
문서가 틀린 게 아니라 그 시점을 담고 있다.

## 디렉터리별 내용

| 디렉터리 | 내용 | 수명 |
|---|---|---|
| `designs/` | 설계 문서. 무엇을 왜 만들고 무엇이 되면 끝인가 | 닫힌 뒤 불변 |
| `adr/` | 아키텍처 결정 기록 | 수락 뒤 불변 |
| `artifacts/` | 프로토타입 | throwaway. 커밋하지 않는다 |
| `specs/` | 개명 전 이름으로 남은 아카이브 | 불변. 새로 만들지 않는다 |
| `plans/` | 없앤 산출물 종류의 아카이브 | 불변. 새로 만들지 않는다 |

`artifacts/`만 `.gitignore` 대상이라 이 리포에는 보이지 않는다.
방향을 실물로 병치해 반응을 받는 용도이고 결정이 설계 문서에 반영되면 역할이 끝난다.

## 더 쓰지 않는 두 디렉터리

`plans/`와 `specs/`에는 새 파일이 생기지 않는다.
둘 다 결정으로 닫혔고 그 안의 파일은 그 결정 이전의 기록이다.

`plans/`는 ADR-0008이 닫았다.
플랜 단계를 없애고 태스크 분해를 실행 시점으로 옮긴 결정이다.
설계 문서 하나가 태스크로 어떻게 갈라지는지는 이제 커밋되는 문서가 아니라 실행 스킬의 진행 기록에만 남는다.

`specs/`는 ADR-0010이 닫았다.
같은 산출물을 `스펙`에서 `설계 문서`로 개명하면서 경로도 `designs/`로 옮긴 결정이다.
`SPEC-0001`은 `status: closed`라 개명 대상이 아니고 옛 이름 그대로 남는다.

## 읽는 순서

groundwork가 왜 지금 모습인지 알고 싶다면 ADR을 번호순으로 읽는 편이 빠르다.
각 ADR이 하나의 결정과 그 대가를 담는다.
`Consequences`의 `Negative`가 기재 의무라서 감수한 위험도 함께 남아 있다.

flow가 실제로 어떤 산출물을 만드는지 보려면 SPEC-0001을 읽는다.
이름은 옛것이지만 담긴 형식은 지금의 설계 문서와 같은 계보다.
